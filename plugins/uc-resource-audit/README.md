# UC 资源变更查询

在 DBX 里选环境、应用和资源，查看操作人、时间、当前状态及可查到的变更。支持使用同一 DBX 里的不同 UC MySQL 连接。

## 安装和使用

[0.1.1 签名包、公钥和仓库目录](releases/v0.1.1/)。

1. 安装 `.dbxp` 后关闭旧工作台标签页，再打开新版。开发包可在「插件中心 → 设置 → 第三方与开发者选项」开启「允许安装未签名开发包」后，通过「安装 .dbxp」选取本地文件。
2. 打开左侧的 UC 数据库连接，右键选择「UC 资源变更查询」。也可以从插件中心打开工作台，再选环境。
3. 在工作台选中环境。首次查询该连接时，DBX 会弹出只读授权，选择允许即可。「已安装 → 数据访问」会显示已经授权的连接。
4. 选择应用，输入资源的名称、编码或数字 ID，再点对应结果。列表显示父级、类型和 ID，便于区分重名资源。

工具自动识别有 `app` 和 `resource` 表的数据库。有多个 UC 库时会显示数据库下拉框。查询复用 DBX 已打开的连接，权限由 DBX 管理。

「资源最后写入」取自资源主记录。历史列表读取环境里可用的字段审计、操作日志和实体操作。只有账号在当前库能唯一对应一个姓名时才会展示姓名。日志以数据库记录的时间为准。

## 打包

在本目录运行 `npx --yes @dbx-app/plugin-cli package . --target universal --output-dir dist`。插件使用 DBX Host API 1.4 的连接枚举和只读查询能力。

## 通过 R2 分发

运行 `pwsh -File ./sign-r2.ps1`。签名包和 `catalog.json` 在 `dist/r2`，可上传到 R2 的同一目录。

在 DBX 的第三方仓库信任设置中添加 `dbx-trust-key.json` 里的 `keyId` 和 `publicKey`，再使用签名包的 R2 地址进行「从 URL 安装」。如果 DBX 隐藏信任设置，先添加自定义仓库，ID 用 `uc-resource-audit-r2`，地址用上传后的 `catalog.json`。

Windows 使用当前用户的 DPAPI 加密保存签名私钥。公钥文件可交给安装者独立核对。
