# UC 运维工具

[0.2.1 签名安装包、公钥和版本目录](releases/v0.2.1/)。0.2.1 修复单位维护工作台中的查找和预览按钮。

在 DBX 里选环境、应用和资源，查看操作人、时间、当前状态及可查到的变更。支持使用同一 DBX 里的不同 UC MySQL 连接。

## 资源变更查询

1. 安装 `.dbxp` 后关闭旧工作台标签页，再打开新版。开发包可在「插件中心 → 设置 → 第三方与开发者选项」开启「允许安装未签名开发包」后，通过「安装 .dbxp」选取本地文件。
2. 打开左侧的 UC 数据库连接，右键选择「UC 资源变更查询」。也可以从插件中心打开工作台，再选环境。
3. 在工作台选中环境。首次查询该连接时，DBX 会弹出只读授权，选择允许即可。「已安装 → 数据访问」会显示已经授权的连接。
4. 按应用名称或编码搜索并选择应用，按资源名称、编码或数字 ID 筛选树形列表，再点资源名称。搜索结果保留父级路径。点「查已删除」可在删除审计中查找。

工具自动识别有 `app` 和 `resource` 表的数据库。有多个 UC 库时会显示数据库下拉框。查询复用 DBX 已打开的连接，权限由 DBX 管理。

资源列表沿用 UC「资源管理」的树形表格，支持按类型筛选。详情显示完整资源路径。「资源最后写入」取自资源主记录。时间线按最新到最早展示，保留创建记录，并可展开原始来源和相关资源关系。时间线分页读取字段审计、操作日志和实体操作明细，展示修改前后值和删除前内容。创建日志缺失时，使用主记录或删除前快照保留的创建人和创建时间。历史范围取决于当前库保留的日志。只有账号在当前库能唯一对应一个姓名时才会展示姓名。日志以数据库记录的时间为准。

## 单位维护

在 MySQL 连接上右键选择「UC 单位维护」，或从插件中心打开。在目标 UC 库按代码、名称、ID 或 UUID 查找单位，选中后填写维护动作并预览。

| 动作 | 生成脚本的范围 |
| --- | --- |
| 修改单位代码 | 默认改外部码、默认部门代码、已确认的 UC 外码引用，并写单位代码变更历史。勾选后也更新内部码和已确认的内部码关系。其他业务字段命中旧码时先核对。 |
| 修改单位类型 | 支持 UC 的单位类型枚举。命中单位树、授权类型或外部单位映射等类型相关记录时，先处理这些依赖。 |
| 删除单位 | 无部门或其他业务引用时删除单位，清理该单位的应用开通记录。现有日志和历史记录可继续查阅。 |

插件通过 DBX 已授权的连接执行只读预览。生成事务脚本后，在 DBX 的独立 SQL 会话切换到同一个 MySQL 实例和数据库，执行并复核返回的 `verification_ok`。值为 `1` 且执行无报错时，在同一 SQL 会话手动 `COMMIT`。值为 `0` 或执行有误时，在同一会话 `ROLLBACK`。

SQL 执行范围是当前 UC 库。iWork 或其他上游管理的单位应通过其改码链路处理。使用脚本后按目标环境的运维流程核对缓存、应用权限和外部系统。命中检查覆盖 UC 已知的单位标识字段，不能替代外部依赖核对。

## 打包

在本目录运行 `npx --yes @dbx-app/plugin-cli package . --target universal --output-dir dist`。插件使用 DBX Host API 1.4 的连接枚举和只读查询能力。

## 通过 R2 分发

运行 `pwsh -File ./sign-r2.ps1`。签名包和 `catalog.json` 在 `dist/r2`，可上传到 R2 的同一目录。

在 DBX 的第三方仓库信任设置中添加 `dbx-trust-key.json` 里的 `keyId` 和 `publicKey`，再使用签名包的 R2 地址进行「从 URL 安装」。如果 DBX 隐藏信任设置，先添加自定义仓库，ID 用 `uc-resource-audit-r2`，地址用上传后的 `catalog.json`。

Windows 使用当前用户的 DPAPI 加密保存签名私钥。公钥文件可交给安装者独立核对。
